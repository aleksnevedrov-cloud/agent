# RFD-SITE-CHAT-AGENT — чат на rf-dveri.ru на базе агента розницы

Розница, ветка `claude/site-chat` от `8d6cbdf` (голова `claude/reactivation-review`, на сервере). Заменяет Jivo: заявка с
контактами и текстом сразу в «Неразобранное» воронки «ДВЕРИ», дальше с клиентом в окне говорит агент розницы «Амма».
Включает ТЗ RFD-SITE-CHAT (окно, форма, запись заявки) и RFD-SITE-CHAT-AGENT (агент в окне).

## 2. Как работает

```
окно на сайте ──POST /site-chat/v1/session──▶ API: строка в базе (amo_sync=pending) ──▶ ответ окну + приветствие
      │                                            │
      │◀── SSE /site-chat/v1/stream (typing, message)│── runSiteTurn (агент розницы, SITE_TOOLS) ──▶ сообщение агента
      │
      └──POST /site-chat/v1/message──▶ то же

воркер site-chat-sync (30 с): заявка «Неразобранного» → примечания → сводка → задача; повторы 1/5/15/60 мин
воркер site-chat-idle (60 с): нет сообщений idleCloseMin → closed, сводка моделью, задача «Перезвонить»
```

Контакты клиента (имя, телефон, почта) модели не передаются — только «контакты есть в заявке». Телефон в фразе передачи
менеджеру показывается самому клиенту. Ссылки в карточках — только `https://*.rf-dveri.ru`.

## 3. Выкладка на сервер

```bash
cd /opt/ai-door/src && git status && git log -1          # на 8d6cbdf, чужих коммитов нет
git fetch origin claude/site-chat && git checkout <хеш коммита RFD-SITE-CHAT-AGENT>
# .env: добавить (см. .env.example)
#   SITE_CHAT_ORIGINS=https://www.rf-dveri.ru,https://rf-dveri.ru
#   SITE_CHAT_ACCOUNT_ID=28528549
docker compose exec -T postgres pg_dump -U aidoor aidoor | gzip > /opt/ai-door/backup-$(date +%F).sql.gz   # дамп
nohup sh -c 'docker compose build api worker && docker compose up -d api worker' </dev/null >/tmp/build.log 2>&1 &
# миграция 026 применится при старте api
curl -s https://ai.rf-dveri.ru/site-chat/v1/health                      # {"status":"ok","enabled":false,...}
curl -sI https://ai.rf-dveri.ru/site-chat/widget.js | head -3           # 200, application/javascript
docker compose logs --since 5m worker | grep -c "site-chat"             # задания завелись
```

nginx для SSE — в `server` для `ai.rf-dveri.ru` (`/etc/nginx/sites-available/ai-door`) добавить отдельный location
перед `location /` и перезагрузить nginx:

```nginx
  location /site-chat/v1/stream {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 120s;
  }
```

Виджет amo 1.3.0 (новая вкладка): `WIDGET_API_URL=https://ai.rf-dveri.ru pnpm widget:build` →
`cp apps/widget/dist/widget.zip /opt/ai-door/dl/widget-9f2c.zip`, заказчик загружает в amo.

Затем в виджете на вкладке «Чат сайта»: проверить тексты и правила, ссылку на политику, всплывание (из Jivo), включить
«Чат на сайте включён». Приёмка — на `https://ai.rf-dveri.ru/site-chat/demo`; потом заказчик ставит строку скрипта
в шаблон UMI. Jivo снимается по его решению.

Откат: в виджете выключить «Чат на сайте» (окно исчезает) или убрать строку скрипта; код — `git checkout 8d6cbdf`,
пересобрать api и worker. Таблицы `site_chat_*` остаются. Если настройки сохраняли после выкладки — в них появился
блок `siteChat`, и строгая схема прежнего кода его не примет: удалить ключ из `widget_settings`.

## 4. Приёмка (раздел 7 ТЗ) — заполняет сессия с доступом к серверу и amo

| Проверка | Ожидаемый результат | Факт |
|---|---|---|
| Клиент отправил форму | заявка в «Неразобранном» «ДВЕРИ» не позднее 10 с, с контактами и текстом | |
| Первый ответ агента | в окне не позднее 20 с, в заявке примечание с вопросом и ответом | |
| «дверь-книжка 340+340, 2000, Дуб Сонома» | агент не переспрашивает размер и цвет; варианты из каталога или честно «уточнит менеджер» | |
| «Позовите менеджера» | передача, сводка в заявке, задача по правилу задач агента | |
| Клиент закрыл сайт после 2 сообщений | через 10 минут сводка и задача «Перезвонить клиенту с сайта» | |
| Переход на другую страницу сайта | переписка на месте, диалог продолжается | |
| Контакт с этим телефоном уже есть в amoCRM | нового контакта нет, заявка привязана к существующему | |
| Агент выключен или бюджет исчерпан | автоответ в окне, заявка создана | |
| amoCRM недоступна (неверный токен на тесте) | агент отвечает, записи доходят после восстановления | |
| Ловушка / 4-я сессия с IP за 10 минут | в amoCRM ничего, агент не вызывается | |
| Телефон | окно на весь экран, переписка работает | |
| Работа агента в WhatsApp/Telegram после выкладки | без изменений, журнал без новых ошибок | |

Сверить на живом аккаунте (п. 0.3 ТЗ, документация amo из среды разработки недоступна): формат ответа
`POST /api/v4/leads/unsorted/forms` (ожидаем `_embedded.unsorted[0].uid` и вложенные `leads`/`contacts`),
`PATCH /api/v4/leads/{id}/notes/{note_id}` для обновления сводки, видимость примечаний в карточке заявки до «Принять».
